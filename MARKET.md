# US market and multi-asset laboratory

Open http://127.0.0.1:8000/#market. The PC must remain awake and the server must remain running. The browser may be closed; the collector and automatic analysis belong to the backend. Stop the download with **Pause download**, or stop compute with **Cancel analysis immediately**. Closing the server stops its managed processes and preserves completed histories. Restart with `start.ps1`; an interrupted collection resumes when automatic resume remains enabled. This is a local background job, not a Windows startup service: restarting Windows requires starting the server and LibreHardwareMonitor again.

## Current full-run configuration

- Provider: Twelve Data, authenticated in the HTTP Authorization header. The key is read from `TWELVEDATA_API_KEY` or `.secrets/twelvedata.key`. It is absent from frontend configuration, request URLs and exported archives. Never commit that file or put a key in a dashboard URL.
- Requested window: 2016-10-28 through 2026-10-27; provider end date 2026-10-28 is exclusive in the cache. Daily `adjust=all` histories include the provider's dividend/split adjustments. No intraday or live trading feed is used.
- Observed account plan: Grow, 55 credits/minute. Collector pacing is 49 requests/minute, leaving some headroom. The account usage response did not supply a daily cap. No account plan, spending setting or subscription was changed.
- Catalogued instruments: 31,957 distinct symbol/exchange/MIC records from the provider's current `/stocks` and `/etfs` US reference endpoints: 20,503 stock-endpoint and 11,454 ETF-endpoint records. Two non-USD records were excluded immediately. The latter endpoint also contains mutual-fund share classes. These are instruments, not 31,957 distinct public companies.
- OTC records are retained in collection and broad correlation research. Missing, unsupported and failed histories are counted explicitly. The catalogue excludes provider-delisted reference entries, and is not a point-in-time historical universe. Provider coverage is not a guarantee of every security ever listed in the US. Aliases, renamed tickers and share classes can refer to overlapping economic exposure; a perfect correlation is a data/issuer-resolution check, not automatically a trading opportunity.
- Each successful instrument's compressed cache survives restarts. Quota-only initial collection time is about eleven hours, with HTTP latency, provider outages, retries and unavailable histories potentially adding time. The dashboard updates the remaining lower bound. It never describes a partial cache as a completed full-market analysis.
- After the queue finishes, the server automatically requests the full eligible correlation matrix, joint factor/conditional models and **100,000 sampled baskets** with sizes 3, 5 and 8, 80% chronological training, seed 42, up to 128 BLAS threads requested, 64 GiB analysis RAM ceiling, 24 GiB OS reserve, 85°C CPU stop, required CPU sensor and six-hour compute duration cap. Actual parallelism depends on the linked numerical library and workload. Windows ProcessPoolExecutor limits the independent basket stage to 61 processes; Linux permits up to 64 here. CPU percentage is measured, never assumed from the thread setting.

The automatic run is armed once per snapshot. A failed or thermally stopped full run does not restart endlessly. The failure remains visible; use the manual analysis button after resolving it. Disabling automatic analysis and saving settings prevents the queued full run. Collection pause/resume is independent of compute cancellation.

## What it computes

1. **Freeze the available cohort.** Each preview records the cache membership at its own start. Current previews are a priority-ordered, incomplete subset, not a representative random sample of the US market. The full run freezes its cohort after every catalogue request has been attempted.
2. **Align observed sessions.** Use the cached SPY weekday sessions as a provider-dependent reference calendar. Stray Sunday/holiday dates in other histories are counted and excluded. Missing prices on valid reference sessions stay missing; no forward filling. SPY coverage itself is a dependency, not an independently audited exchange calendar.
3. **All eligible pair correlations.** Calculate daily log returns. Training eligibility requires minimum overlap, nonzero variance and a minimum active-return fraction. Every pair of eligible instruments is evaluated using exactly the observations present for both. Insufficient-overlap pairs stay missing. Store the full row-major float32 matrix on disk; export the strongest retained neighbors as CSV. The CSV is intentionally smaller than the full matrix.
4. **A joint, many-asset model.** Require 95% training coverage and a conservative exchange-traded/liquidity screen for the core model: listed common stocks, ADRs, REITs, ETNs, or funds explicitly named as ETFs, with at least $1 million median training price-times-volume daily turnover. This avoids treating mutual-fund share classes as easily traded baskets, but can exclude valid ETFs whose names lack an ETF marker. It does not establish borrowability or true execution liquidity. Standardize training returns and impute the small remaining gaps at training means. PCA describes shared variation; ridge precision estimates conditional association after controlling for the other core assets. Use a dual Gram/Woodbury calculation when instruments exceed observations, avoiding a cubic inversion of a huge asset matrix. These statistics do not establish cause or expected returns.
5. **Exposure networks.** Connect strong positive training-correlation neighbors into components. Connectivity is transitive: two assets in one component need not themselves have high correlation. These are research groups, not independent risk buckets.
6. **Multi-asset basket search.** Reproducibly sample a mixture of conditional-neighbor baskets and random baskets from the screened core. Test weighted log-price relationships using Johansen trace statistics with a constant and one lagged difference. Prioritize mixed-sign, non-full-rank baskets where every normalized coefficient has at least 2% absolute weight, so a negligible extra leg does not disguise a pair as a many-asset relationship. Rank this group by training evidence. Freeze coefficients and training spread statistics, then evaluate the fixed spread in the later period. Use the longest consecutive complete segment in each period rather than collapsing missing-date gaps. Reject unstable or genuinely complex numerical fits. Ranks use nominal 5% critical values; no fabricated Johansen p-values are reported. The later ADF p-value is separately Bonferroni-adjusted across every attempted basket. Combinations grow too quickly to enumerate exhaustively; the report records both actual trial count and theoretical search spaces. More trials improve coverage of hypotheses, not the amount of independent financial evidence.
7. **Strategy experiments.** For leading training-ranked mixed-sign baskets, show an illustrative mean-reversion experiment. Signal at a close affects the next interval; positions use fixed adjusted-price units between entry and exit, with entry gross notional equal to equity. Enter at absolute z-score 2–4, exit below 0.5, above 4, after 20 sessions or at evaluation end. Charge configured turnover costs and modeled short borrow. Funding, stock availability, market impact, taxes, execution gaps and live orders are absent.

The portfolio experiment is a predefined long-only alternative: choose the highest training-turnover qualifying representative per correlation component, take up to 32 representatives, weight by inverse training volatility, cap each holding at 10%, keep residual cash, and rebalance monthly. Show later returns, drawdown, Sharpe and costs, alongside buy-and-hold SPY on exactly the same observed dates with the same entry/exit cost. A longest complete evaluation segment can be shorter than the overall later window; its actual dates are shown. Inspect those dates before comparisons.

## Using results to develop a strategy

First examine stable common factors and redundant exposures. Then compare the predefined diversified baseline and a small, training-selected set of genuinely distinct basket hypotheses. Check tradability, short availability, turnover, drawdowns and behavior in different market regimes. Highly correlated assets often mean duplicated exposure rather than an opportunity.

The current implementation has a single chronological split, not a complete walk-forward strategy-validation system. Inspecting and retuning against later results makes those observations development data. Before an investment decision, freeze a specification, obtain historical constituent/delisted coverage where needed, run a proper walk-forward comparison against simple benchmarks, and evaluate a fresh forward paper-trading interval. The software places no orders and has no broker connection.

## Resources and reproducibility

- RAM fields are ceilings, not allocations or targets to fill. The matrix uses disk-backed storage and row tiles; basket futures are bounded. Summing process RSS counts shared mappings more than once and is deliberately conservative. Reports show actual eligible/core cohorts and actual worker count.
- Collector: 2 GiB process RSS ceiling, 24 GiB available-memory reserve and 16 GiB compressed-cache limit per snapshot. Provider failures retry with pacing; denied/unavailable histories are recorded. A process lease prevents duplicate collectors. A 429 pauses and retries; an invalid key blocks collection rather than attempting account changes.
- Analysis: independent memory/time watchdog, CPU sensor requirement, configured temperature stop, and process-tree cancellation remain active outside the compute worker. Disk-space preflight reserves the estimated log/matrix size plus 10 GiB. Analysis directories remain local for reproducibility; repeated previews create more matrices, so periodically archive or remove unneeded completed analysis directories while no analysis is running. No 192 GiB or full-machine memory stress was needed to obtain useful results.
- CUDA is not implemented for this market workspace. Its expensive work uses NumPy/BLAS and independent statistical workers. The original simulator's optional CUDA source is unchanged; nvcc is unavailable, so GPU performance remains unmeasured.
- Cache: `data/market/snapshots/<snapshot>/`; collection status: `data/market/collection.json`; saved queue policy: `data/market/control.json`; bounded latest report: `data/market/latest.json`; matrix, log-price array, instrument order, full successful basket CSV and neighbor CSV: `data/market/analysis/<analysis_id>/`.
- `MARKET_REPORT.json` and `MARKET_VALIDATION.json` are a measured cached-subset preview, not a full-market conclusion. `MARKET_CANCEL_VALIDATION.json` records the real process-pool cancellation check. Private credentials and raw downloaded price caches are excluded from the source ZIP.

Primary references: [Twelve Data API](https://twelvedata.com/docs), [credits](https://support.twelvedata.com/en/articles/5615854-credits), [usage endpoint](https://support.twelvedata.com/en/articles/5713553-control-over-api-usage), [Johansen test](https://www.statsmodels.org/stable/generated/statsmodels.tsa.vector_ar.vecm.coint_johansen.html), [ADF test](https://www.statsmodels.org/stable/generated/statsmodels.tsa.stattools.adfuller.html).

## Setup on another machine

Run `setup.ps1` and then `start.ps1` from this project directory as described in README.md. Before collection, put the API key in a local `.secrets/twelvedata.key` file (create the `.secrets` folder if needed), or set `TWELVEDATA_API_KEY` for the server process. The current machine is already configured. Start LibreHardwareMonitor as administrator with its loopback sensor endpoint enabled on port 8085. The archive intentionally omits the key and downloaded histories. Fresh installations default to 20,000 baskets; set 100,000 in the dashboard and save full-run settings to reproduce the queued workload policy.
